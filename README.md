# tg-poll-tagbot

Бот, который по команде тегает участников группового чата.

**Команды** (слэш-командой или начиная с тега бота; регистр не важен, `teg`/`tag` — оба):

| команда | что делает |
|---------|-----------|
| `/tagall` **реплаем на опрос** | тегает тех, кто **не проголосовал** |
| `/tagall` **без реплая или реплаем на любое др. сообщение** | тегает **всех**, кроме автора — **только админ чата** |
| `/tagstop @user` | больше **не тегать** этого человека в этом чате — **только админ** |
| `/tagback @user` | снова тегать — **только админ** |
| `/help` | список команд (также `/помощь`, `/команды`) |

Замьюченные (`/tagstop`) не попадают ни в общий тег, ни в теги по опросам. Список
хранится по чатам в `muted.json`. Боты, удалённые аккаунты и автор команды (для
общего тега) исключаются автоматически.

## Как это устроено (и почему «гибрид»)

Telegram **запрещает бот-аккаунтам** читать список проголосовавших в опросе
(`messages.getPollVotes` — «Only users can use this method»). Поэтому:

- **Бот** (из @BotFather) — только интерфейс: принимает команду и пишет теги в чат.
  Всё видимое в чате — от имени бота.
- **Ваша user-сессия** — работает **только на чтение**: список участников чата
  и список проголосовавших. Ничего не отправляет.

Вход в user-аккаунт делается **один раз** (номер + код из Telegram). Дальше сессия
хранится локально в `.user_session`, и бот запускается без каких-либо подтверждений —
как ещё одно ваше устройство в Telegram. Отозвать доступ можно в любой момент:
Telegram → Настройки → Устройства → завершить сессию.

## Ограничения

- Работает и в супергруппах, и в обычных группах. В обычных группах id сообщений
  у бота и у аккаунта-читалки различаются, поэтому бот находит опрос под читалкой
  по глобальному `poll.id` (сканирует последние ~300 сообщений чата).
- Только **неанонимные** опросы (в анонимных Telegram не отдаёт, кто голосовал — никому).
- User-аккаунт (читалка) должен **состоять в чате**. Голосовать вручную не нужно:
  Telegram отдаёт список проголосовавших только тому, кто сам голосовал
  (`POLL_VOTE_REQUIRED`), поэтому бот при необходимости **голосует читалкой
  автоматически, читает список и сразу отзывает голос** — счётчик опроса
  возвращается к прежнему значению, свой служебный голос из списка вычитается.
  Если проголосовать нельзя (quiz, закрытый опрос, запрет переголосования) —
  бот попросит проголосовать вручную.
- Если в чате **скрыт список участников**, сделайте user-аккаунт админом чата.
- Очень большие чаты: Telegram отдаёт примерно первые ~10 000 участников.

## Установка

```bash
cd tg-poll-tagbot
python3 -m venv venv
venv/bin/pip install -r requirements.txt
cp .env.example .env
```

### 1. Токен бота (@BotFather)

1. Напишите [@BotFather](https://t.me/BotFather) → `/newbot` → задайте имя и username.
2. Скопируйте токен в `.env` → `BOT_TOKEN`.
3. Рекомендуется: `/setprivacy` → выберите бота → **Disable**
   (тогда бот надёжно видит команду в группе; с включённым privacy сработает,
   только если вы именно `@упомянули` бота или использовали `/tagall`).

### 2. Свои api_id / api_hash

Зайдите на <https://my.telegram.org> → **API development tools** → создайте приложение.
Скопируйте `api_id` и `api_hash` в `.env`. (Используйте свои, а не чужие — общие ключи
рискуют упереться во флуд-лимиты.)

### 3. Одноразовый вход user-аккаунта

```bash
venv/bin/python login_user.py
```

Введите номер телефона, затем код из Telegram (и пароль двухфакторки, если есть).
Создастся файл `.user_session`.

### 4. Добавьте бота и user-аккаунт в чат

- Добавьте **бота** в целевой групповой чат.
- Убедитесь, что **user-аккаунт** тоже состоит в этом чате.

## Запуск

```bash
./run.sh
```

Бот работает, пока запущен процесс. Держите его в `tmux`/`screen` или запустите
в фоне. Проверка в логах: строка `чтение: … | интерфейс-бот: @…` и `готов.`

## Прокси (для хостинга, где MTProto режется напрямую)

Если хостите там, где до MTProto-ДЦ Telegram нет прямого доступа (например
Yandex Cloud / РФ-ДЦ), поднимите локальный SOCKS5 (напр. Xray/sing-box через
VPN-выход вне РФ) и укажите его в `.env`:

```
PROXY_TYPE=socks5        # socks5 | socks4 | http
PROXY_HOST=127.0.0.1
PROXY_PORT=10808
# PROXY_USER=...         # если прокси с авторизацией
# PROXY_PASS=...
```

Пусто → прямое подключение (на машинах, где Telegram доступен напрямую, напр.
локально на Mac). Нужен пакет `python-socks` (уже в `requirements.txt`).

### Как это развёрнуто сейчас (Yandex Cloud)

ВМ `tg-poll-tagbot` (ru-central1-b). Прямой MTProto из YC заблокирован, поэтому:

- `xray` (systemd-сервис) держит SOCKS5 `127.0.0.1:10808` → VLESS+Reality на
  не-РФ VPN-сервер; конфиг `/usr/local/etc/xray/config.json`.
- `tg-poll-tagbot` (systemd, `After=xray.service`) запускает бота с `PROXY_*`
  в `.env`. Оба сервиса `enabled` → автостарт после перезагрузки.

Управление на ВМ:

```bash
systemctl status tg-poll-tagbot xray
sudo journalctl -u tg-poll-tagbot -f      # логи бота
sudo systemctl restart tg-poll-tagbot
```

### Watchdog: автопочинка тоннеля

`deploy/xray_watchdog.py` → на ВМ `/usr/local/bin/xray-watchdog`, запускается
systemd-таймером каждые 5 минут. Что делает:

1. проверяет, ходит ли трафик до Telegram через SOCKS;
2. если нет — тянет свежий список серверов из ссылки-подписки
   (`/usr/local/etc/xray/subscription.url`, root-only), перебирает ноды,
   переключает Xray на первую рабочую и перезапускает бота;
3. пишет владельцу (`OWNER_ID` в `.env`) в Telegram — **через Bot API напрямую**,
   без тоннеля, поэтому уведомление доходит даже когда VPN лежит. Если рабочих
   нод нет — напоминает не чаще раза в час.

```bash
systemctl status xray-watchdog.timer
sudo journalctl -u xray-watchdog -n 50    # что делал watchdog
sudo /usr/local/bin/xray-watchdog         # прогнать вручную
```

Смена VPN-подписки = заменить ссылку в `/usr/local/etc/xray/subscription.url`.

## Использование

**Тег непроголосовавших (реплаем на опрос):**
1. В чате есть **неанонимный** опрос.
2. User-аккаунт (читалка) один раз голосует в этом опросе.
3. Любой участник отвечает **реплаем на опрос** командой `/tagall`
   (или `@ваш_бот tagall`; варианты с `teg` тоже работают).
4. Бот пишет упоминания всех, кто не проголосовал.

**Тег всех:** отправить `/tagall` без реплая — **или реплаем на любое сообщение,
которое не опрос** → бот тегает всех, кроме автора команды (и замьюченных/ботов/
удалённых). **Доступно только админам чата** — чтобы обычные участники не спамили.
Права проверяются через аккаунт-читалку.

**Мьют человека (только админ):** `/tagstop @username` — этого человека больше не
тегают в этом чате (ни в общих тегах, ни по опросам). Вернуть — `/tagback @username`.
Указать можно и через `@упоминание` безымянного (тапнув по имени).

Ответы бота на разные ситуации:
- реплай не на опрос → подсказка;
- анонимный опрос → объяснение, что данные недоступны;
- читалка не голосовала → просьба проголосовать;
- скрытые участники → просьба сделать читалку админом;
- некого тегать → «Все проголосовали 🎉» / «Некого тегать 🎉»;
- мьют без указания кого → просьба указать `@username`.

## Тесты

```bash
venv/bin/pip install -r requirements-dev.txt
venv/bin/python -m pytest -q
```

Покрыты чистые функции (`tests/`): парсинг конфига/прокси, чтение сессии,
извлечение id голосовавших (старый/новый слой TL), сборка упоминаний с
HTML-экранированием, распознавание команды (слэш/тег бота, регистр, негатив),
фильтр непроголосовавших, пагинация `_collect_voters`, кастом-эмодзи в
сообщениях, генерация QR-SVG и права `.user_session` (0600). Сеть не нужна.

## Файлы

| файл | назначение |
|------|-----------|
| `bot.py` | демон: bot-клиент (интерфейс) + user-клиент (чтение) |

## Безопасность

Не коммитьте `.env` и `.user_session` (уже в `.gitignore`). Строка сессии = полный
доступ к вашему Telegram-аккаунту. Отзыв: Telegram → Настройки → Устройства.
